# Scaffold

- Logic: `pnpm turbo gen create-game --args <Name>` inside the dev container works.
- UI: `pnpm turbo gen create-game-ui --args <slug>` fails (`t.choices.find is not a function`: plop cannot bypass a list prompt whose choices are a function). Render `turbo/generators/templates/game/ui/**` yourself: copy every file to `games/<slug>-ui/`, and in `.hbs` files replace `{{kebabCase game}}` and `{{properCase game}}`, turn `\{{` into `{{`, and drop the `.hbs` suffix.
- Copying the latest title's packages from its branch (`git archive <branch> games/<t> games/<t>-ui | tar -x`), then renaming and rewriting, carries every lesson already applied (layout, toggles, history panel, animator, scenario generator) and was faster than the template for YINSH and DVONN. Sweep the copy for the old title's words (`grep -rniE` for its pieces and features) before calling it done. Include dotfiles and configs. `postcss.config.js` must call `createGameUiPostcssConfig` from `@tabletop/rolldown-config/postcss`, which takes the scope from `GameInfo.id`; an older copy with its own hard-coded `[data-game-ui="<slug>"]` prefix silently drops every rule and `:root` variable when copied (MATRX: the table rendered unstyled, its variables computing to empty).
- The templates predate the coding policy. Before building on them:
  - replace `<GameDefinition<…>>{…}` with `defineGame({ info, runtime })` (see `games/magna-grecia/src/definition/definition.ts`);
  - remove `as` casts (`game.config as …`, `turnOrderSorted … as …`, `gameSession as …`): read config through a pure `fooFromConfig(config)` that falls back to the default, and narrow the session with `assert(gameSession instanceof FooGameSession, …)`;
  - pin `@typescript/native-preview` to the version the sibling games use (the template writes `*`);
  - in `src/app.html`, make the viewport tag `width=device-width, initial-scale=1, maximum-scale=1, viewport-fit=cover`. Without `maximum-scale=1`, iOS browsers zoom in when a text field under 16px is tapped (the harness's new-game name fields) and stay zoomed through reloads, which clips the table's right edge and hides the bottom of the board under the browser toolbar. Without `viewport-fit=cover`, `env(safe-area-inset-*)` reads 0, so the shared layout cannot clear the home indicator or notch. The template is upstream; fix each title rather than the template;
  - keep the harness page's `UiDefinition as unknown as GameUiDefinition<…>`: every title has it and the readiness checks expect it.
- The templates also fail the readiness review (`pr-readiness.md`) until, in each new title:
  - the four dependencies the templates declare and no title uses are removed: `es-iterator-helpers` (logic), `javascript-time-ago`, `nanoid` and `@floating-ui/dom` (UI);
  - `info.ts` declares `visibility: GameVisibility.Alpha` beside `beta: true`, as upstream's newest titles do, and `runtime.ts` declares `randomnessVersion: 1`;
  - the UI package has a `vitest.config.ts` (see `ui-lessons.md`, *Session tests*), or its unit tests never run from the repo root;
  - `playwright.config.ts` runs the dev harness on the title's own port with a smoke spec in `tests/` (`browser-checks.md`, *Smoke spec*); the template's build-and-preview server with no tests makes the package's `test` script fail;
  - the colorizer overrides `allowPreferredPlayerColors()` to return `false` when player colours are the printed pieces' colours (White and Black), or a preferred colour swaps a player's name badge against their pieces. Titles whose player colours only mark seats (ZÈRTZ, LYNGK) keep preferences.
- Delete the template `cover.jpg` once the title has its own cover. Commit covers as lossy WebP 680 px high, twice the large catalog card's height (`tools/gipf-covers/webp.py`); the review fails a JPEG cover. Commit no alternative covers: an image nothing imports fails it too.
- Run `pnpm install` in the container after adding packages; the lockfile changes with them.
