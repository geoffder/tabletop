# Animation lessons

The `game-ui-animation` skill owns the contract; these are the bugs earlier titles shipped and fixed. One board animator (a `TransitionStep` listener on the session) per title has been enough.

- **Kinds.** Animate only `own-action`, `other-action`, `undo`, `history` and `exploration`; return early on `initial`, `reconciliation`, `view-switch` and `edit`, or a page refresh replays the last move. Check: reload, open the game, and compare screenshots 0.1 s and 1 s later; they must be pixel-identical.
- **Diff the two boards by piece id, at every step.** With ids in State (`logic.md`), `boardDiff(from, to)` maps each id to where it stands in each board: pieces that leave one place together for another are one run (with what they left below and landed on), pieces only in `to` appeared, pieces only in `from` vanished, and a step that changes nothing adds no motion. The animator draws an in-between board (`from` without the pieces in flight, plus arrivals) and one flier per run, keyed by its first id. Undo, another player's Undo, a step back and a jump over many moves then all play from the same diff, and the session passes the animator no moves (`games/tzaar-ui/src/lib/board/boardDiff.ts`; LYNGK and PÜNCT alike). Take from the action only what the boards cannot hold: LYNGK's route through its LYNGK points, or, for a step with an action, its metadata (DVONN builds a move's change from `MoveStack`'s metadata, so a landing stack that is itself cut off still hops, lands and floats away). For a step back, the undone action is the one whose `index` is `to.actionCount`. The review replaced every title's inference and `historyMove`/`knownMove` plumbing with this; the next three lessons are the fallback for a title without ids.
- **Action-less steps.** Undo and state-only history pass no action. Read the move from the `from`/`to` boards (a jump: same colour two points away in line with the middle changed; a push: some entry that turns one board into the other) and play it quickly (≤ 0.18 s), backward too. A rule like "a piece whose spot changed fades" is wrong: it lifted a jumping marble as if captured, and faded every pushed piece. Fade only what left the board. Unit-test the inference both ways.
- **Infer a move by its geometry, not only its pieces** (DVONN): a cut-off single piece matched "the stack that left one space and now tops another" before the real mover did. Require the hop the rules allow (in line, as far as the stack is tall).
- **Reset reused nodes.** Elements keyed by board spot are reused for whatever piece lands there next. Symptom: a piece is missing after Undo and reappears after an unrelated move. Collect every node the timeline touches and reset `x`, `y`, `scale`, `opacity` in `afterAnimations`. Check: after undo and history steps, every piece's group has opacity 1.
- **Actions run ahead of the state shown.** `session.actions` updates at commit, before the animation plays. Symptom: an effect derived from the latest actions (sunken-ring shadows) changes instantly instead of with the move. Derive from `session.actions.slice(0, session.gameState.actionCount)`. They can also arrive late: a hosted game opens with its state and loads its actions afterwards, replacing `actions` alone, so anything derived from them must track `session.actions` too (the PR bot: ZÈRTZ's marbles kept stand-in specks after history loaded).
- **Remembered choices come from the actions on screen** (PÜNCT's last way round), so Undo and history restore them.
- **Layers.** A moving piece flies on a layer above the board so it never passes under another piece or ring. Outlines and marks live on their own layer, not inside the group that animates, so a removed piece sinks without its outline; the layer is keyed on `session.gameState` so the next position's marks fade in fresh. Fade each mark node on its own on the move's timeline, never the layer or a group: `docs/phone-rendering.md` counts opacity below 1 on a group as an offscreen effect, and the review moved every title's mark fade onto the nodes (register each with the animator's `mark()`, and `gsap.set(node, { clearProps: 'opacity' })` on landing).
- **Placed pieces must not wait for the state.** Symptom: a placed marble appeared, vanished, then appeared again. The board draws the previous state until `afterAnimations`, so between the click (which clears the preview) and the end of the outline fade the space was empty. For a placement, write the new board to the drawn state at the start of the transition, before any tween; the outlines then fade over the placed piece.
- **A staged piece lifts off only when its player lets it go.** A view switch, History, an exploration or a new state that clears the selection removes it without its lift-off. The session sets a flag whenever the player changes the selection, cleared when a state is published, and exposes `releasedByPlayer` (the flag, and not in History View), which the piece's outro reads (`c7d160278`).
- **Staged previews** (a piece dropping onto the chosen entry dot) explain a selection, not a commit, so the staged piece owns its motion: GIPF gives each staged piece a small GSAP timeline created when it mounts and killed when it unmounts, adding each part's tweens as the part's attachment registers. Key it by spot and piece type, so choosing the other type on the same dot drops it in afresh; a preview that compares only position missed a change of kind and kept drawing the old piece (the PR bot, on PÜNCT). Taking the choice back (Undo, or another dot) lifts it off with an `out:…|global` transition whose function asks, when the outro starts, whether the piece is going in instead; if it is, return `{ duration: 0 }`.
- **Transitions in nested blocks.** Symptom: the staged marker stopped dropping into the chosen ring. Svelte 5 plays an `in:` transition only when its own block is created; inside a `{#key}` nested in an `{#if}`, the outer block creates it on the first choice and the drop never runs. Mark it `|global`.
- **Placement drops.** A piece fading in at its space reads as appearing. Drop it from about a row's height, opaque within the first quarter, gathering speed (`power2.in`, 0.26 s), with a small bounce (4 units, 0.14 s); keep its shadow in a separate node that waits on the space, small and faint, and darkens as the piece lands. Undoing a placement is the drop in reverse: the piece lifts off gathering speed (`power1.in`, 0.3 s), fading over the last 40%, the shadow shrinking under it. `power2.in` for the lift crammed the climb into the last moment, so it seemed to vanish. Within the 0.18 s undo budget (GIPF), rise about 30 units with `power1.out` and fade separately with `power2.in`, so the piece is seen rising before it goes; a lift and fade sharing one ease read as a fade. The user liked the drop and may want it in other titles with placement.
- **Undo reverses the live motion.** Pieces taken off come back moving the reverse way (a lifted row drops back in, one after another), and stepping forward through history repeats the live motion quickly; a plain fade either way reads as a different event.
- **Pieces changed by a passing piece** (YINSH's flipped markers) change along its path, lift while they turn, and are drawn above it, so they pop up as it slides beneath.
- **A chain's next choice waits for the whole timeline.** The new state, and with it the next targets, lands only when every tween ends, so a slow decorative tail holds up a player who moves again at once. ZÈRTZ's next jump of a capture chain opened 670 ms after the landing click: the captured marble's 0.55 s lift, started partway through the jump, ended last. A quicker lift for captured marbles (0.3 s; claimed marbles kept 0.55 s) and a shorter landing rebound (0.045 s steps) brought it to 480 ms. Measure it: click the landing target from a page script, then poll each `requestAnimationFrame` until the next target exists.
- **Pace.** Every millisecond of the move animation delays the next turn. Single moves around 0.3–0.6 s (Sol: 0.3–0.5 s); 0.85 s felt slow. Group follow-on effects with small offsets (claimed marbles lift, rings sink 0.1 s later).
- **Nothing reactive is written on each frame.** A tween's `onUpdate` that sets `$state` makes Svelte redraw every frame (PÜNCT's hover; TZAAR's and DVONN's shrinking cap). Write poses straight to the nodes (next lesson); step a reactive change at a few `timeline.call` points (the cap shrinks one whole piece per call over 0.3 s); keep objects GSAP drives in `$state.raw`. For a custom progress, tween an object whose setter does the work, `{ at: 0, get u() { return this.at }, set u(u) { this.at = u; pose(u) } }`, never `onUpdate`, `onStart` or `onComplete`, and derive visibility from the value, since a seek can land anywhere. The occlusion clock in `tilted-view.md` is one.
- **Move SVG through a pose, never GSAP's own transform.** GSAP writes an SVG node's `x`, `y` and `scale` as `matrix()`, and Firefox 140 leaves a `matrix()` offset out of the CSS zoom that `renderAtViewScale` draws the board under: under zoom 0.5 a test square landed at x=300 instead of 150, so moving pieces spread apart. Give every moving node a pose object (`x`, `y`, `scale`) and tween that; the pose writes `translate(x y) scale(s)` to the node itself. Opacity stays on the node. Copy `animators/svgPose.ts` from `gipf` (`09ee9f3ba`), with `poseOf`, `setPose`, `tweenPose`, `fromToPose` and `killPose`. A `matrix()` you build yourself fails the same way: YINSH's turning marker became `translate(e f) matrix(a b c d 0 0)`. Split every `to(node, { opacity, y, scale })` into a pose tween and an opacity tween, with `fromTo(…, { immediateRender: true })` for drops placed later in the timeline, so the piece is hidden from the start of the step.
  - **Write from the pose's setters, not from `onUpdate`.** A timeline moved by `seek()` suppresses callbacks, so an `onUpdate` that writes the transform leaves the piece where it last drew. MATRX and GIPF with Potentials first wrote from `onUpdate`, and ZÈRTZ's frame-capture checks found pieces stuck mid-move (`matrx` `a3023efa8`).
  - A pose scales about the node's own origin, so draw each moving node centred on 0,0 and translate it to its point; no `svgOrigin` is needed, and its measuring cost (next lesson) goes with it.
  - **Test it**: `tests/motion.spec.ts` (`gipf` `dbb96354f`) installs Playwright's clock, pauses it, starts each move, Undo and history step from a page script, and reads every node's `transform` and `style` inside the board over 30 frames of 20 ms, so Svelte transitions are covered too. It fails on any `matrix(` with an offset (YINSH allows `matrix(a b c d 0 0)`). Cover every motion the title has, including a preference's (DVONN's stack limit) and every return motion: the PR bot flagged GIPF's dropped-back rows as untested.
  - **Check that the rewrite moves nothing.** Seek the old and new code's timelines to the same times and compare the frames. GIPF with Potentials matched in all 625 frames; MATRX stayed within 0.85 px, inside the variation between two runs of the old code.
- **No `svgOrigin` once moves use poses**: the review removed every call. Before poses, titles set `gsap.set(node, { svgOrigin: '0 0' })` so scale tweens grew from the piece's centre; if one is ever needed, set it only on the nodes a move is about to scale, as the move starts. Each call measures the node's whole drawing (`getBBox`) and parses its transform: DVONN set it on three nodes per stack as they attached, and opening a game froze for 2.5–4 s; MATRX GIPF set it on every disc as it attached, and opening froze for 10 s on a phone-sized page while taking 0.15 s on desktop. Set it inside the function that starts the scale tween, never in an attachment.
- **The `AnimationContext`'s timelines run from creation.** Work done before adding tweens skips their start: drawing the flier and occluders took about 45 ms, so a hop appeared already 26 units up. Build the motion in a child timeline and place it at the real time elapsed since the listener started, capped at 0.01 s (`Math.min(DRAW_WAIT, waited)`, DVONN), or the wait breaks an actionless step's 0.2 s budget.
- **One route per move.** When the route a piece takes does not change the move's outcome (LYNGK chains), choose it by a fixed rule (the shortest) in one function, and call it from the move, undo and history, so all three play the same path.
- **Looping effects** (LYNGK's lightning between linked points): step the shape with SVG `<animate attributeName="d" calcMode="discrete" repeatCount="indefinite">`; swapping shapes with CSS opacity blinked. Cycle about six distinct seeded shapes forward only: with three, the jump back to the first stood out, and playing them back and forth read as a wiggle. About 3.6 shapes a second felt right. Every extra shape costs one stored path string, nothing per frame.
- **Stacked pieces drop disc by disc** (GIPF-pieces are two discs): draw each disc on its own node centred on its own base, drop the bottom one, and drop the top one onto it 0.1 s later (the user tuned it down from 0.14). The crease between them is the top disc's shadow on the bottom one's face: its own node in the bottom disc, fading in as the top disc comes down. Taking a stack off lifts it whole; the user did not want it to separate.
- **Who drops a piece in.** Only your own move has a staged piece already standing on its dot; another player's move and a full-action history replay must drop the piece in before it slides, or it appears on the dot from nowhere. Test `kind === 'own-action'`, not `kind === 'other-action'`. Choose the quick path by `action === undefined`, not by `kind === 'history'`: a history replay carries its action and plays the full move, drop included (MATRX first played replays at Undo speed, so the stack appeared on its dot).
- **`afterAnimations` runs before the state lands.** The presenter runs the callbacks as soon as the timeline ends and publishes the new state after an `await`, so the page renders in between. Symptom (GIPF): a ghost piece flew off after every push. Clearing the entering piece in `afterAnimations` let the staged piece, derived from a selection the new state had not yet cleared, mount again, start its drop, and lift away when the selection cleared. Keep such flags until the state lands: a writable `$derived` that reads `session.gameState` and returns its resting value, set by the listener (`pushedIn = true`), resets itself when the state is published.
- **A view switch can abandon a run.** If `publishNow('view-switch')` lands while a move plays (a reload after a rejected or stale move), the presenter shows that state and publishes nothing for the run, yet its `afterAnimations` callbacks still fire. An override the callback writes (the board's pieces, a returned piece) then covers the state shown, and nothing corrects it. Note `const shown = session.gameState` when the listener starts and apply such overrides only if it is still the state shown; reset nodes and clear transient pieces either way. In a replay every step's `from` is freshly hydrated, so compare against the noted state, not `from`.
- **One animator per node.** A GSAP tween and a Svelte `out:` transition on the same element fight: the CSS transform and opacity of the transition override the attributes GSAP writes, so a half-dropped disc removed mid-drop snaps to rest before lifting off. Put the outro on a wrapper with the GSAP node inside it, and have the transition function kill the inner node's tweens when it starts (`gsap.killTweensOf(child)` for each child), so the disc rises from where the drop left it; an attachment's cleanup runs only once the outro ends, so without that the drop keeps falling under the lift and the disc dips first. Check it inside the page: script both taps with `dispatchEvent` and sample the node's box each animation frame, since a Playwright click plus screenshot takes longer than a 0.18 s outro.
- **Undoing a committed placement goes back to the staged choice** (the user's ask for GIPF): the first Undo slides the piece back onto its dot, where it stands staged as chosen; the next Undo lifts it off, and one more clears the piece type, if there was a type to choose. Wiring:
  - The session overrides `willUndo(action)` to remember the action, and `beforeNewState({ kind })` to restore the selection on `kind === 'undo'` instead of clearing it. `incomingGameState` holds the restored state there, for checks such as whether there was a type to choose.
  - The animator slides the piece to its dot and, in `afterAnimations`, leaves a transient standing piece there until the state lands. Give it the same key and the same template branch as the staged preview that the restored selection draws, so the handover does not remount it (no second drop).
  - Stepping back through history still lifts the piece off where it stands.
- **Only your own Undo restages.** Another player's Undo reaches you as `kind: 'undo'` with no action, and so does a step back; if the animator stands the piece on its dot as for your own Undo, nothing restages it, and it lifts off by its outro after the publish, outside the move. Stand it there only when the session says this Undo is its own (`restagedMove(to)`); otherwise slide it back and lift it off in the same timeline (slide 0.14 s, lift from 0.08 s for 0.12 s: within an actionless step's 0.2 s).
- **Let the session stop a move.** A view switch publishes at once and stops no timeline, so a move's tweens run on over the new state; turning the board mid-move leaves them aimed in the old view. The session keeps `moveInterrupters: Set<MoveInterrupter>`, and each animator stops only its own motion: it keeps its child timeline or the set of objects it tweened, and its landing as a `land` closure (also passed to `afterAnimations`); `interrupt()` kills them (`gsap.killTweensOf([...tweened])`) and calls `land()`, and `abandon()` does the same and notes `session.presentingState`, so it skips the rest of that replay. `beforeNewState` calls `abandon()` on `view-switch`; every preference that changes layout or drawing calls `interrupt()` (far side, 90°, stack limit, coordinates, which change the phone layout). An animator the change cannot affect does nothing (LYNGK's claim strip on a board turn), and the board's detach stops its animator. GIPF, MATRX GIPF and ZÈRTZ instead play the shared timeline to its end with `progress(1)`; the five later titles, reworked by the maintainer, use the set, so follow them (`games/tzaar-ui/src/lib/model/session.svelte.ts`). Check with a fake clock (`page.clock.install()` before `goto`), interrupting 120 ms in: the state lands at once and no board node is left off rest.
- **Keep what was on screen in `beforeNewState`, not an `$effect`.** ZÈRTZ's animator needs the actions shown before a history jump, but by the time a step plays the session has moved on. It first copied them in an `$effect` that needed a justification for review. The session's `beforeNewState` runs before every publish while the outgoing state is still shown, so it calls the animator's `replacingShown()` there, which keeps the live game's and an exploration's actions apart (`zertz` `f854fecab`).
- **A step back reads the undone move by index.** `onHistoryAction` names the action before the one a step back undoes; use the action on screen whose `index` is the new `actionCount`.
- **The boards cannot always name where a piece came from** (titles without piece ids). A push that moved nothing along could have come from any of the dots beside its spot (three, in GIPF); inference picked the first, so Undo and history slid the piece to the wrong dot. Pass the action when the session knows it: the one being undone (`willUndo`), or the one history stepped to (`onHistoryAction`, which runs before each step is presented). Use it only when it turns one board into the other, and otherwise fall back to inference. A hosted Undo presents twice (optimistically, then the server's replay), so the second pass finds equal boards and must move nothing.
- **All of a step's motion goes on the step's timeline**: no Svelte `crossfade`, `animate:flip` or `Tween` for game motion. They run outside the presenter, play on `edit` and reconciliation, and ignore the Undo budget. LYNGK's claim strip first used crossfade and TZAAR raised its frame with a `Tween`; both moved onto the timeline.
- **Tokens moving between HTML strips** (LYNGK's claimed colour flying from the neutral pieces to a player's side): a FLIP on the step's timeline, in an animator of its own (`games/lyngk-ui/src/lib/animators/claimAnimator.svelte.ts`). On each step it measures each token where it stands, sets the landing state (a writable `$derived`), awaits `tick()`, measures again, tweens a progress object on `animationContext.actionTimeline` that writes each token's `transform` (0.62 s, 0.18 s without an action), and clears the inline styles in `afterAnimations`. Mirror the second player's list so a new item lands on the outer end and nothing there moves. The motion the user liked: lift 10 px, arc 16 px over the straight path, touch down 14 px short, skip 4 px, slide in; 0.62 s. Undo plays it back the same way.
- **A hovering staged piece** (PÜNCT): the piece you place or move hovers a little more than its thickness above where it will rest until you confirm. Give it a motion object of its own (`StagedMotion`) holding the whole piece and a pose (plan position, height, shadow height, angle, aloft) whose setters write straight to the nodes, drawn from the motion, not from the selection. No `$effect` feeds it: the session keeps `stagedFollowers` and calls them through a `followStaged()` batched with `queueMicrotask`, from every selection change, `beforeNewState` and `setViewingAsNonActivePlayer`. Its attachment's cleanup stops the motion (`staged.clear()`), or its timeline runs on after the board is gone (the PR bot). Then the commit lands it in the action's timeline and `afterAnimations` clears it, Undo raises the board piece back into its hover before the session restages it (`follow` sees the same piece and leaves it), and the board, which excludes the hovering piece's id, needs no flags.
  - **Placing**: it falls to where it would rest, bounces off up past the hover (0.45 of its thickness) and settles into it; a fall into a bounce that settled at the hover read as a settle, not a bounce.
  - **Moving**: it lifts straight off where it stands, then flies over everything into the hover.
  - **Turning** (tap it, or the prompt's button): it pivots about its anchor dot, `power2.inOut`, the way chosen, the other way if anything taller than the hover stands under that sweep, and if both are blocked it lifts clear, turns and comes down. Test the sweep against the spaces under sampled poses along the piece's bars.
  - **Draw it over what it sweeps.** Ordered only by the spaces it ends on, a turning piece passed under nearer pieces it was swinging over; give it the spaces it sweeps as its own for the draw order while it turns, and draw it over everything while lifted or flying.
- **Several fliers, keyed by id.** A history jump over many moves flies every moved, taken and returned piece straight between its two ends, one flier per run, keyed by its piece's id (YINSH's rings, DVONN's bottom pieces), with each flier's parts in a `Map` that drops a key when its last part detaches. Occluders (`tilted-view.md`) are needed only while a single flier is in the air.
- **Overlap two motions to keep both within the 0.2 s budget.** An actionless step that must move a piece and bring another back plays both in 0.12 s phases, the second starting at 0.06 s (`QUICK = 0.18`, `QUICK_PHASE = 0.12`, DVONN, TZAAR, LYNGK). The maintainer kept every title's return motions this way rather than dropping one.
- **A move committed during a staged drop carries on from where the drop is.** Make the staged drop's pose a pure function of time, shared by its Svelte transition and the animator; the session records when the intro started (`onintrostart`), and the animator finishes the drop from there before the move (YINSH `board/dropIn.ts`).
- **Hand a piece between board and tray at the moment it moves.** A step that brings a piece in sets the reserves it leads to as the step starts (`landingReserves`), the tray leaves out the staged piece, and a piece leaving the board reaches its card as it lifts (`timeline.call(() => { this.land(run); session.landScores(after) }, undefined, at)`); Undo takes it off the card as it drops back. A spec on a paused clock checks it is never drawn in both places (`games/lyngk-ui/tests/motion.spec.ts`).
- **A piece moved and then removed by the same action** passes from flier to board at the landing time (`timeline.call`), so the removal animates the whole stack. The flier draws the piece's decorations itself (DVONN's height badge) and moves them with it.
- **Animator safety.** Wrap `present(step)` in a `try`/`catch` that clears the fliers and rethrows; throw when a node the step needs is missing (`'A flier is drawn before it flies'`) rather than returning quietly. The session logs a listener's exception to the console and goes on, so make the browser specs fail on console errors (`browser-checks.md`).
- **History View has no transitions on highlights** (a tray's set highlight changes at once there), and an Undo asserts the state it presents.
- **Animator helpers are private methods** of the animator, not free functions beside it.
