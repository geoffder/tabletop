# Animation lessons

The `game-ui-animation` skill owns the contract; these are the bugs earlier titles shipped and fixed. One board animator (a `TransitionStep` listener on the session) per title has been enough.

- **Kinds.** Animate only `own-action`, `other-action`, `undo`, `history` and `exploration`; return early on `initial`, `reconciliation`, `view-switch` and `edit`, or a page refresh replays the last move. Check: reload, open the game, and compare screenshots 0.1 s and 1 s later; they must be pixel-identical.
- **Action-less steps.** Undo and state-only history pass no action. Read the move from the `from`/`to` boards (a jump: same colour two points away in line with the middle changed; a push: some entry that turns one board into the other) and play it quickly (≤ 0.18 s), backward too. A rule like "a piece whose spot changed fades" is wrong: it lifted a jumping marble as if captured, and faded every pushed piece. Fade only what left the board. Unit-test the inference both ways.
- **Infer a move by its geometry, not only its pieces** (DVONN): a cut-off single piece matched "the stack that left one space and now tops another" before the real mover did. Require the hop the rules allow (in line, as far as the stack is tall).
- **Reset reused nodes.** Elements keyed by board spot are reused for whatever piece lands there next. Symptom: a piece is missing after Undo and reappears after an unrelated move. Collect every node the timeline touches and reset `x`, `y`, `scale`, `opacity` in `afterAnimations`. Check: after undo and history steps, every piece's group has opacity 1.
- **Actions run ahead of the state shown.** `session.actions` updates at commit, before the animation plays. Symptom: an effect derived from the latest actions (sunken-ring shadows) changes instantly instead of with the move. Derive from `session.actions.slice(0, session.gameState.actionCount)`.
- **Layers.** A moving piece flies on a layer above the board so it never passes under another piece or ring. Outlines and marks live on their own layer, not inside the group that animates, so a removed piece sinks without its outline; the animator fades the whole mark layer on the move's timeline for the move's duration, and the layer is keyed on `session.gameState` so the next position's marks fade in fresh.
- **Placed pieces must not wait for the state.** Symptom: a placed marble appeared, vanished, then appeared again. The board draws the previous state until `afterAnimations`, so between the click (which clears the preview) and the end of the outline fade the space was empty. For a placement, write the new board to the drawn state at the start of the transition, before any tween; the outlines then fade over the placed piece.
- **Staged previews** (a piece dropping onto the chosen entry dot) explain a selection, not a commit, so the staged piece owns its motion: GIPF gives each staged piece a small GSAP timeline created when it mounts and killed when it unmounts, adding each part's tweens as the part's attachment registers. Key it by spot and piece type, so choosing the other type on the same dot drops it in afresh. Taking the choice back (Undo, or another dot) lifts it off with an `out:…|global` transition whose function asks, when the outro starts, whether the piece is going in instead; if it is, return `{ duration: 0 }`.
- **Transitions in nested blocks.** Symptom: the staged marker stopped dropping into the chosen ring. Svelte 5 plays an `in:` transition only when its own block is created; inside a `{#key}` nested in an `{#if}`, the outer block creates it on the first choice and the drop never runs. Mark it `|global`.
- **Placement drops.** A piece fading in at its space reads as appearing. Drop it from about a row's height, opaque within the first quarter, gathering speed (`power2.in`, 0.26 s), with a small bounce (4 units, 0.14 s); keep its shadow in a separate node that waits on the space, small and faint, and darkens as the piece lands. Undoing a placement is the drop in reverse: the piece lifts off gathering speed (`power1.in`, 0.3 s), fading over the last 40%, the shadow shrinking under it. `power2.in` for the lift crammed the climb into the last moment, so it seemed to vanish. Within the 0.18 s undo budget (GIPF), rise about 30 units with `power1.out` and fade separately with `power2.in`, so the piece is seen rising before it goes; a lift and fade sharing one ease read as a fade. The user liked the drop and may want it in other titles with placement.
- **Undo reverses the live motion.** Pieces taken off come back moving the reverse way (a lifted row drops back in, one after another), and stepping forward through history repeats the live motion quickly; a plain fade either way reads as a different event.
- **Pieces changed by a passing piece** (YINSH's flipped markers) change along its path, lift while they turn, and are drawn above it, so they pop up as it slides beneath.
- **Pace.** Every millisecond of the move animation delays the next turn. Single moves around 0.3–0.6 s (Sol: 0.3–0.5 s); 0.85 s felt slow. Group follow-on effects with small offsets (claimed marbles lift, rings sink 0.1 s later).
- Use `gsap.set(node, { svgOrigin: '0 0' })` on wrappers centred on their point so scale tweens grow from the piece's centre, and set it only on the nodes a move is about to scale, as the move starts. Each call measures the node's whole drawing (`getBBox`) and parses its transform: DVONN set it on three nodes per stack as they attached, and opening a game froze for 2.5–4 s; MATRX GIPF set it on every disc as it attached, and opening froze for 10 s on a phone-sized page while taking 0.15 s on desktop. Set it inside the function that starts the scale tween, never in an attachment.
- **The `AnimationContext`'s timelines run from creation.** Work done before adding tweens skips their start: drawing the flier and occluders took about 45 ms, so a hop appeared already 26 units up. Build the motion in a child timeline and place it at the real time elapsed since the listener started (DVONN's animator does this; the shared code is unchanged).
- **One route per move.** When the route a piece takes does not change the move's outcome (LYNGK chains), choose it by a fixed rule (the shortest) in one function, and call it from the move, undo and history, so all three play the same path.
- **Looping effects** (LYNGK's lightning between linked points): step the shape with SVG `<animate attributeName="d" calcMode="discrete" repeatCount="indefinite">`; swapping shapes with CSS opacity blinked. Cycle about six distinct seeded shapes forward only: with three, the jump back to the first stood out, and playing them back and forth read as a wiggle. About 3.6 shapes a second felt right. Every extra shape costs one stored path string, nothing per frame.
- **Stacked pieces drop disc by disc** (GIPF-pieces are two discs): draw each disc on its own node centred on its own base, drop the bottom one, and drop the top one onto it 0.1 s later (the user tuned it down from 0.14). The crease between them is the top disc's shadow on the bottom one's face: its own node in the bottom disc, fading in as the top disc comes down. Taking a stack off lifts it whole; the user did not want it to separate.
- **Who drops a piece in.** Only your own move has a staged piece already standing on its dot; another player's move and a full-action history replay must drop the piece in before it slides, or it appears on the dot from nowhere. Test `kind === 'own-action'`, not `kind === 'other-action'`. Choose the quick path by `action === undefined`, not by `kind === 'history'`: a history replay carries its action and plays the full move, drop included (MATRX first played replays at Undo speed, so the stack appeared on its dot).
- **`afterAnimations` runs before the state lands.** The presenter runs the callbacks as soon as the timeline ends and publishes the new state after an `await`, so the page renders in between. Symptom (GIPF): a ghost piece flew off after every push. Clearing the entering piece in `afterAnimations` let the staged piece, derived from a selection the new state had not yet cleared, mount again, start its drop, and lift away when the selection cleared. Keep such flags until the state lands: a writable `$derived` that reads `session.gameState` and returns its resting value, set by the listener (`pushedIn = true`), resets itself when the state is published.
- **Undoing a committed placement goes back to the staged choice** (the user's ask for GIPF): the first Undo slides the piece back onto its dot, where it stands staged as chosen; the next Undo lifts it off, and one more clears the piece type, if there was a type to choose. Wiring:
  - The session overrides `willUndo(action)` to remember the action, and `beforeNewState({ kind })` to restore the selection on `kind === 'undo'` instead of clearing it. `incomingGameState` holds the restored state there, for checks such as whether there was a type to choose.
  - The animator slides the piece to its dot and, in `afterAnimations`, leaves a transient standing piece there until the state lands. Give it the same key and the same template branch as the staged preview that the restored selection draws, so the handover does not remount it (no second drop).
  - Stepping back through history still lifts the piece off where it stands.
- **The boards cannot always name where a piece came from.** A push that moved nothing along could have come from any of the dots beside its spot (three, in GIPF); inference picked the first, so Undo and history slid the piece to the wrong dot. Pass the action when the session knows it: the one being undone (`willUndo`), or the one history stepped to (`onHistoryAction`, which runs before each step is presented). Use it only when it turns one board into the other, and otherwise fall back to inference. A hosted Undo presents twice (optimistically, then the server's replay), so the second pass finds equal boards and must move nothing.
- **Tokens moving between HTML strips** (LYNGK's claimed colour flying from the neutral pieces to a player's side): a pair of transitions like Svelte's `crossfade`, with your own path. The leaving element records where it stood and vanishes at once; the arriving one, in its deferred config, flies in from there. The sender's deferred config must keep its record while a receiver is waiting for it (symptom: nothing flew). Make one pair per strip instance: full screen draws a second copy of the strip. Use `animate:flip` on the items so the rest close up, and mirror the second player's list so a new item lands on the outer end and nothing there moves. The motion the user liked: lift 10 px, arc 16 px over the straight path, touch down 14 px short, skip 4 px, slide in; 0.62 s. Undo plays it back the same way.
