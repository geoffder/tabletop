# Table UI lessons

Each lesson names the symptom a user saw, so you can recognise it.

## Layout

- **Player cards.** Size a label column to its longest label (`max-content`), not a fixed width, so the space goes to the pieces.

- **Action panel height.** Symptom: the board jumps when the turn changes. Make the action panel one fixed-height message row, as Bus and Magna Grecia do: the last move while you wait, the prompt with its buttons inline on your turn, the step shown in history view. Anything else that always shows (a pool strip) sits below at a constant height. Check by reading the board's `getBoundingClientRect().y` on your turn, while waiting and in history: all equal.
- **Banner text.** Keep the banner's move text to one line: a brief form ("pushed ⚪ from D1 to D2, taking row D2–D5"); full detail (shifted counts, returned and captured counts) belongs in the history panel. One builder with a `brief` flag serves both.
- **Spaces in rich text.** Symptom: "removed B2and claimed". Svelte trims whitespace at the edges of `{#if}`/`{#each}` blocks. Build history lines as segments (text, piece, point) with the spaces inside the text segments, and test the joined text.
- **Coordinates.** Use the published notation in capital letters, laid out as BoardSpace lays out that game, which differs by game: open BoardSpace's own picture of the board first. ZÈRTZ, GIPF and LYNGK label each column with its bottom point's name below it (A1) and its top point's name above it (A4), where separate letters above and numbers along the sides collide and read as wrong names; YINSH puts the letters under the columns and the numbers before each line on the left. Labels sit about 0.6–0.72 × spacing from their point; compare the frame margin with sibling titles.
- **Player areas off the board** (YINSH's ring spaces) belong to a seat, not to the viewer. Symptom: a removed ring flew to one corner and then appeared in the other. The harness switches viewer after every action, so viewer-relative sides swap mid-animation. Fix each player's side by turn order, matching the order of the player cards.

## Phones

- **Height budget.** Symptom: the board is small on a phone. On a phone the board is limited by height, so every row above it shrinks it. Keep each strip above the board one row on phones: a player's name beside their pieces, the name truncating first. Check the board's size at the phone sizes in `browser-checks.md` before and after the change.
- **Zoom bar.** Symptom: the bottom-left label hides under the zoom controls. Leave room in the board's `viewBox` below the bottom labels for them, and keep the board centred at full size. `ScalingWrapper` clips its content, so the bar cannot be nudged outside it, and a band reserved above the board with `insetTop` costs board size on every phone.
- **Cards beside the board** (DVONN): `DefaultTableLayout` (upstream) gives the phone game column `min-w-[90vw]` and a 320px sidebar, so a strip of the cards crowds the board. The title's `GameTable` overrides it under 40rem: game column `min-width: calc(100vw - 20px)`, which leaves 12px of the cards showing as a hint, sidebar 260px, tab icons hidden (the tabs need 309px with icons, 237 without).
- **Overlay toggles** (light/dark) sit in an empty corner of the board's outline, where the fitted board leaves room, so the board needs no band reserved for them. Put a new toggle on the row of an existing one: stacked one per row, ZÈRTZ's third toggle came down onto the top coordinate label on phones.

## Marks and highlights

- Draw highlight outlines thin (about 1.4, 2 when emphasised), on their own layer above the pieces, with radius `edge + gap + width / 2` so a thicker hover line grows outward and never covers the piece, and small enough that neighbouring outlines never meet. Where pieces touch (ZÈRTZ's rings, packed as on the table), draw the outline just inside the edge instead, `edge − inset − width / 2`, so it stays on its own piece.
- Mark a piece with something on its own top face (a spot, a recoloured existing ring) rather than a ring around it: large rings overlap neighbours. A toggle mark can recolour a feature the piece already has (a GIPF-piece's crown ring: green keep, red take).
- Offer a toggle only where both choices are sensible for the player; keep the rules engine permissive.
- **Tap off to let go** (every title since MATRX GIPF): a tap on anything on the board that cannot be chosen lets go of the staged board choice, as tapping another choice already switches it. The session's `letGo()` clears the first board stage through the title's staged-selection helper and does nothing when nothing is staged; the board `<svg>`'s `onclick` returns when `event.target instanceof Element` and `closest()` finds an enabled choosable element (`[role="button"]:not([aria-disabled="true"])`, or the title's own target class), and otherwise calls `letGo()`. Things that cannot be chosen must let the tap through: aria-disabled, `pointer-events: none`, or no button role. Silence `a11y_click_events_have_key_events` and `a11y_no_noninteractive_element_interactions` on the svg with a `svelte-ignore`, as NAPOLEON'S TRIUMPH does, with a comment that Undo lets go from the keyboard. Panel preferences kept between turns (a piece type, a marble colour picked automatically) and a row's keep toggles stay. Record it in the visual contract's staged-selection line and regression checklist.
- **Once one choice is made, the others fade** to 40% (MATRX GIPF, GIPF's push dots): stacks you could move and dots you could push from stay visible and tappable, so switching is one tap.
- **Hover previews on touch.** Symptom (iPhone): a tapped ring flashed the hover preview, then showed nothing until the move landed. A tap fires pointer enter and leave around the click; ignore enter when `event.pointerType === 'touch'`.
- Fade outlines rather than removing them; see `animation-lessons.md` for fading them with the move.
- **Marks on stacked or tall pieces** (DVONN): draw each mark inside its piece's group, after the piece but outside the group that animates, so pieces in front cover it as they cover the piece; keep them registered with the animator so all of them fade with the move.
- **Dashed marks on light pieces**: outline each dash on its own rather than laying the dashes on a solid dark band. The black dashes are shorter but square-capped, overhanging each coloured dash by the outline width; the piece shows between dashes.
- **Selection rings on HTML tokens** (a claim strip) lie on the ground around the piece, flattened by the board's tilt. Draw them inside the token's piece icon SVG, behind the piece, with `vector-effect="non-scaling-stroke"` so the cyan and its 1px dark edges keep their pixel widths; keep the ring's room on tokens with nothing to choose, so the strip never shifts. **Measure** the clearance between neighbouring rings (bounding rects minus each ring's reach) at desktop and phone widths before reporting it; one round reported rings as less cramped while they overlapped by 3px on phones.
- **Show the whole network.** A mark explaining reach (LYNGK's lightning between linked stacks) comes from the board's geometry, not from the legal moves: derived from moves, a link with no landing beyond it was never drawn.

## Pieces and contrast

- **Pack pieces as the real game does.** ZÈRTZ's rings touch on the table; the first version left a gap that the user removed.
- Size pieces in one geometry module, as large as the tightest neighbouring pair allows, with a unit test asserting the gap (≥ 0, small) so later tweaks cannot introduce overlap.
- Keep details crisp when zoomed: draw the piece without SVG filters, and speckles as real seeded circles, not a `<pattern>`.
- Draw shadows as radial-gradient fills, not a blur filter over a group of them. Symptom (YINSH, on an iPhone; not reproduced in Chromium): a removed ring's shadow stayed until the next move, consistent with WebKit not repainting under a filter whose children were removed.
- A panel that shows a black piece needs a light background (trays, history panel, history list icons). On a light table, give faded controls (history buttons) a dark backing.
- Light/dark toggles: an icon showing the mode a press switches to (moon on light, sun on dark), with a matching `aria-label`.
- **Text and controls standing on the table** take their own variables (`--<slug>-table-ink`), apart from the ink of dark panels, so a table colour change cannot leave pale text on a pale table.
- **CSS order.** A phone `@media` rule placed before the desktop rule for the same selector never applies: equal specificity, so the later rule wins. Symptom (LYNGK): the claim strip's compact phone spacing never took effect, crowding the second player's name to "B…". Put media blocks after the rules they override; [`../scripts/media-order.py`](../scripts/media-order.py) `<branch>...` lists every such rule in each title's UI package.

## Stacks

From DVONN, where stacks reach 20 pieces and only the top colour and the DVONN pieces inside matter.

- **Counts beside marked tops** (TZAAR): when the top piece carries markings that matter (gold and silver centres), a count over the centre hides the type. The user compared counts in the centre, smaller in the centre, on the ring and on a badge, on a crowded scenario at phone size, and chose a white badge with a black number on the near-right of the top piece, inside the stack's own outline. A badge on the far rim read as belonging to the stack behind. Draw the badge after the top's marks, so a mark ring passes under it.
- **Small text in SVG drifts on phones.** Symptom (TZAAR, 390 wide at 1×): badge digits sat low and right of their circle. Text a few pixels tall is snapped to whole pixels. Set it ten times larger inside `scale(0.1)`, and centre it with an explicit `dy` (0.36em for digits) rather than `dominant-baseline`.
- **Height must be unmistakable.** Put the count on the top piece (DVONN: in the donut's hole, white outlined in black, for stacks of two or more), and let the stack rise as a physical pile up to a cap, thinning every band above the cap instead of rising further. Show the user the cap as a labelled grid of heights on a scenario where it hides the most (flat view: 10; tilted view: 13, judged by the share of the pieces behind left showing, see `tilted-view.md`).
- **Where a tall stack hides most**: the two neighbours in the row behind it, which overlap it sideways; the space straight behind stays clear. Keep a harness scenario with pieces, stacks and a special piece in those spaces.
- **Pieces that matter inside a stack** (DVONN's red pieces) keep most of their band's thickness (0.8) when the rest thin out, capped at half the stack's rise. Symptom: a buried red piece became a 1px line.
- **Seams between same-coloured dark pieces** on a flat view: black bands with a black edge run together. A faint white catch-light along the top of a black band whose piece has another black piece on it parts them; none on the top piece and none between different colours. On the tilted view, nested pieces with a seam gap part already, and the user switched the catch-light off.
- **Donuts are see-through.** Leave the hole open: down it draw each piece's inner wall at its true thickness (even where its outside band is thinned), with a thin seam between pieces, clipped to the top opening; below the last wall the board shows. Symptom: a tall thinned stack showed sand down its hole. A white piece's inner wall needs to be pale (the shadowed grey read as a dark smudge against the sand).
- **Speckles belong to the piece, not the place.** Symptom: a piece's speckle pattern changed as it hopped onto another stack. Seed each piece by an identity stored in game state (DVONN records `placedAt`, the space it was placed on; LYNGK keeps an optional `ids` list per point, the deal index of each piece, moved with its stack), never by space and level; hand-built scenario pieces each need a distinct identity, or a stack's pieces share one pattern. Keep the identities optional, so saved games from before them load and fall back to space and level.

## Player cards

- **Tally what players count** (GIPF, after DVONN): each row is a bold count, a one-word caption (`reserve`, `GIPF`, `captured`) and the pieces themselves drawn small with the board's piece shape, in stacks.
  - **Choose the stack cap from the title's counts**, so the largest count a row can show still fits on one line beside its caption. GIPF's rows hold at most 18 pieces, and the user chose stacks of 3 over 4. DVONN's cards count up to the whole board (49): once phone cards narrowed to 260px, stacks of 8 left the pieces small, and the user chose 10 (five stacks at most). Show the user two caps side by side.
  - **Draw both cards' tallies at one size.** Symptom (DVONN): a card holding many stacks shrank its pieces to fit, so the two cards drew pieces at different sizes. Give the tally the room right of the caption (`flex: 1`, a `max-height`) and a `viewBox` always as wide as the most stacks the game can need, right-aligned (`xMaxYMid meet`). Captions that change with the phase (`left` while placing, `high` after) sit overlaid in an inline grid, the hidden one `visibility: hidden`, so each takes the wider word's room and the tally keeps its size; the user also picked the shorter `left` over `to place` for this.
  - A special piece shows as itself, each GIPF-piece as its own two-disc stack, never gathered into taller stacks.
  - Captured pieces show in the opponent's colour.
  - Give the count column a fixed two-digit width so both cards' captions line up.

## Session tests

Rune classes such as the session only react when compiled for the client; under the SvelteKit plugin's server build, a `$derived` read in a test stayed at its first value. Give the UI package its own `vitest.config.ts`, as Hill Country Grocers does: the plain Svelte plugin, `resolve.conditions: ['browser']`, the `$lib` alias, and `config/config-vitest/clientRunesEnvironment.ts` as the environment. The root Vitest projects then pick the package up too. Then:

- Build the session with `createHarnessAppContext` and a local game whose seat has the harness user's id (`harness-user`), and stub `saveGameLocally`.
- `await session.waitForVisibleTransitionSettled()` after constructing it and after every action, Undo and history step. Until the first presentation settles the session is busy and ignores actions without an error. History also holds its stepping lock until a `setTimeout`, so wait one timer between steps.
- Stub `addEventListener` and `removeEventListener` globally: title preferences listen for window focus, and the client environment's `window` is Node's global.
- `new URL(path, import.meta.url)` becomes an asset lookup in the client build (`self is not defined`); build file paths with `fileURLToPath(import.meta.url)` instead.
- Check a new test fails with the fix switched off.

## Table textures

- **A background that runs past the board** (YINSH's storm of cloud): an image inside the board's SVG is clipped at the board's frame by `ScalingWrapper`. Draw it on a layer behind the table instead, positioned from the board's `getScreenCTM()` so it lines up with the board through fitting, zoom and pan (observe resizes and the wrapper's `style` changes). Make the layer `absolute` inside the table, so it scrolls with the table on phones, and `fixed` only inside the full-screen dialog.
- **A board with margins and rounded corners** (DVONN's sand board): SVG clip paths ignore strokes, so a polygon stroked wide with round joins draws the shape but cannot clip a texture to it. Compute the outline offset by the margin, with an arc at each corner, and use that path for both.
- **A printed edition's colours**: when the user points at the rulebook, take the table from it too (DVONN: the rulebook's red, glowing orange towards the middle), and warm every panel, tab and history control to match rather than leaving the earlier titles' navy. On the red table the user chose sand panels (`#e3ddd0`, a little lighter than the board's sand) over white or dark warm ones, each card keeping its coloured name band. Put the shade in one variable (`--<slug>-panel`) and derive hover, input and disabled shades with `color-mix`, so trying a shade is one override.
- **Generated textures.** `feTurbulence` piped through `feColorMatrix` must set the color in the matrix's offset column and take alpha from a noise channel; otherwise the clouds come out grey-black and darken everything. Noise warped by `feDisplacementMap` shows seams when tiled, so draw one large image. Filter noise gave laminar streaks or random marbling; the look the user wanted (one storm centred on the board, with eddies) came from tracing thousands of faint streaks along a wind field on a canvas, shown as an image.
- **Pre-render generated art; never compute it as the game opens.** Piece drawings of more than a few dozen elements count too: see `performance.md`, *Pre-rendering piece looks*. YINSH's storm was traced on the main thread at every page load: opening a game froze for 5 s (longer on phones), in production as much as in the harness. Anything seeded and deterministic, such as a canvas texture or a traced pattern, is the same every time, so render it once with a script in the UI package (`scripts/render-<name>.mjs`, run as `pnpm run render-<name>`) and commit the images to `src/lib/images`. Import them like the cover image, and the bundle emits them as hashed assets. Keep the drawing in its own module that only the script runs, with a comment at the top naming the command to rerun after changing it. YINSH's `scripts/render-storm.mjs` draws in headless Chromium with Playwright, so the result matches the browser's canvas exactly. It serves the module from source with `page.route` and Vite's `transformWithEsbuild`, then writes `canvas.toDataURL('image/webp', 1)`. Lossless WebP came out half the size of a PNG and smaller than lossy WebP for one-colour streaks on transparency. The browser check "Opening a game" catches a regression.

## Full screen and zoom

- `ScalingWrapper`'s full screen is a modal dialog with a dim backdrop, so the table background vanishes. Render the same background class as a `position: fixed; inset: 0; z-index: -1` layer inside the `toolbar` snippet while expanded.
- Let small boards fill the space: `maxFitScale` above 1, `maxScale` for zoom, `renderAtViewScale`.
